# Native Registry

Generated by `tools/Generate-NativeRegistry.ps1`. Do not edit by hand.

265 routines are admitted for every naturally observed call at
their address. Across those routes 758,035 of 1,171,207 observed
calls (64.7%) were proven native; the remainder fall back to emulated
assembly by design, because the dispatcher returns no replacement for a
state it has not been proven against.

## Measured cycle share

Deploying the registry with `--replace-registry` over the 3,600-frame
Release state-census route (`--native-cycle-census`, measured 2026-08-08):

| | |
| --- | ---: |
| Elapsed master cycles | 1,289,956,401 |
| Native master cycles | 275,458,359 |
| **Native share** | **21.35%** |
| Routines installed | 263 of 265 |
| Routines entered | 196 |
| Calls run natively | 639,938 of 1,023,720 entered |
| Calls declined at an interrupt horizon | 3,599 |

The resulting state census is byte-identical to the assembly-only
baseline (`9036a9de…`), so that 21.35% is faithful, not merely running.
Two admitted routines are withheld from that run because each changes the
census on its own — `02:57E9` and `03:6054`. Both are proven `@all` on an
unpatched route, but their regressions assert a census hash that differs
from the baseline, so the change was blessed per-routine and is inherited
by any run that deploys them. Adding them back with explicit hooks still
completes 3,600 frames, at a census (`fe61e05b…`) that is not the
assembly one.

The hold-back is not a flag on the measurement command: it lives in
`kWithheldRoutines` in `src/app/main.cpp` and applies to every composed
deployment, so the interactive host runs the same faithful 263 that this
measurement does. Each run names them in its deployment summary.

## Cycle budget

A whole-ROM `--instruction-profile` of the same route (8,977 executed
addresses, 1,292,378,139 master cycles) shows what the remainder is:

| Category | Share of all cycles | Share of working cycles |
| --- | ---: | ---: |
| Frame-sync spin loop (`00:E323`/`00:E325`) | 45.21% | — |
| Timer IRQ handler (`00:FC00`–`FDFF`) | 13.73% | 25.05% |
| Video banks (`08`, `09`, `45`) | 13.73% | 25.05% |
| Gameplay pool | 27.34% | 49.90% |

Nearly half the machine is idle: `00:E323` is `CMP $00` / `BEQ -4`,
spinning on the VBlank counter 24.2 million times. That is the game
waiting, not working, so it is not a porting target and it is the slack
that absorbs anything the port makes faster. The `TIMER` vector points at
`$FC00`, so the second row is interrupt-context work.

The video row is no longer wholly out of scope. `08:40DF`, the satellite
attribute-table emitter, is 7.77% of all master cycles on its own and now
runs natively for every call, so the portable pool is the 353,331,747-cycle
gameplay pool plus its 100,468,839 cycles. Against that 453,800,586, the
275,458,359 native cycles are **60.7%** — a very different figure from
21.35% of everything, and the one that reflects how much of the portable
game actually runs natively.

The largest unported clusters are now the timer-handler ranges and the
remaining video work: `08:4036-40DE` (28,276,836 cycles) and banks `09`
and `45`. The former `01:C4F1-C536` and `01:CA84-CB92` candidates are the
native `01:C510` and `01:CB48` scans.

Cycle share is concentrated: `08:40DF` alone is 7.60% of all master cycles
and `01:CC1A` (collision vertical scan) 5.30%, with the top five addresses
at 17.01% of the 21.35%. 69 installed routines are never entered on this
route and 48 more are entered without ever accepting a call.
